# 产品主线

## 1. 定位

个人知识库 + 写作编辑器。形态上类似 Obsidian 与印象笔记的结合：本地优先的桌面应用，一边是“什么都能往里丢”的 AI 知识库，一边是支持 Markdown 与 LaTeX 实时渲染的写作编辑器，辅以文章/电子书阅读管理。

## 2. 核心理念

以下来自用户原话（原 `requirement.txt`），是知识库设计的根本出发点：

> 我想要的大概就是无脑的往里面填信息，塞文章，应该是他来帮我整理的。文件夹应该也是他来帮我建的，tag 他来帮我打，然后有 agent 问所有问题，再打通我的眼镜。
>
> 我的逻辑是喂屎进去，比如录音直接怼进去，并不是好好写笔记的逻辑（听着跟 datalake 一样，屎坑，还能查询，能帮你整理，打 tag，帮你分门别类）。
>
> 知识库是高频写入，低频读取的，跟 log 差不多，哪有空天天整的好好的，只能靠 AI 来整，文件夹可以考虑是虚拟的。
>
> 这个要整很多 agent，还能把语音转写总结呢，总结还会丧失信息，你还得把原始文件留着，总结只是索引。笔记这玩意儿确实高频写入低频读，而且读的时候还是短期集中频繁读。大部分是冷数据，少部分热数据。

提炼为设计原则：

| 原则 | 含义 |
|------|------|
| 写入零成本 | 输入要够快够“无脑”：快捷键唤起、拖拽、粘贴、录音一键导入，不要求用户先分类 |
| 整理归 AI | 打标签、建文件夹、归类、转写、总结都由 Agent 完成，用户不需要花时间整理 |
| 原始数据永久保留 | 总结会丢信息，只作为索引；原始录音/文件/文章必须保留 |
| 虚拟文件夹 | 文件夹是规则或 AI 生成的视图，不是真实目录，一条内容可出现在多个视图 |
| 冷热分层 | 大部分是冷数据，读取时短期集中频繁读；存储与检索按此优化 |
| 可问答 | 通过 Agent 对整个知识库提问，未来打通眼镜等设备 |

## 3. 三大模式

| 模式 | 快捷键 | 功能范围 |
|------|--------|----------|
| 知识库 knowledge | ⌘1 | 快速输入（⌘N 文本 / ⌘⇧R 录音，支持图片、文件、网址）；条目流（搜索、类型/标签筛选、分组、列表/卡片，虚拟滚动）；详情面板（AI 解读 / 原始内容 / 关联）；智能文件夹与手动文件夹；侧栏面板（标签云、录音管理、日历与日记、最近）；全局与局部知识图谱（链接层 + 实体与实体关系层）；基于知识库的问答（带来源引用）；Agent 后台转写、摘要、打标签、语义索引与关联发现，进度浮窗实时展示；自动归类生成待审阅建议，逐条接受 / 修改 / 拒绝 |
| 写作 writing | ⌘2 | Typora 式 Markdown 所见即所得（光标处显示语法标记、输入即渲染、斜杠命令、表格、任务列表、公式、分块渲染），文档以标准 Markdown 存储；LaTeX（`.tex`）源码 / 渲染 / 分栏；纯文本；`[[双向链接]]`、`[[笔记#标题]]` 与块级引用 `[[笔记#^块]]` 补全与跳转；反向链接面板（反链、出链、未链接提及、局部图谱）；大纲；代码块高亮与补全；标签页与两栏同时编辑；专注模式；页面设置（纸张背景、页宽、排版、打字机模式）；版本历史与分层保留；拼写检查（Hunspell，含复合词规则） |
| 阅读 reading | ⌘3 | 书架（网页、书签、文档自动上架）；可调排版、目录与滚动高亮、阅读进度记忆、书签；PDF / EPUB 应用内阅读，扫描版 PDF 本地文字识别；高亮（PDF 可跨页）与摘录入库（摘录自带 `[[来源]]` 链接）；链接中的标题 / 块在阅读视图内定位 |

通用：多知识库（独立数据库与附件，标题栏切换）、Ribbon 侧栏面板、设置面板（AI 服务商与对话/向量/转写模型、自动处理开关、外观、版本保留、插件）、插件系统（Worker 沙箱、权限授权、⌘⇧P 命令面板、状态栏）、浅色 / 深色 / 跟随系统主题与强调色、子窗口。用户文档见 [USER_GUIDE.md](./USER_GUIDE.md)。

## 4. 不做什么

- **代码阅读器**：有了 AI 之后代码变得廉价，不再做代码浏览、代码阅读模式、Monaco 代码查看器。
- **代码分析类功能**：依赖分析、依赖图、流程图、代码笔记关联、GitHub 仓库读取。
- **独立的 CLI / Web / UI 组件库子包**：已删除，产品只交付桌面端。
- **多套编辑器 UI**：始终只有一个编辑器，按文件类型切换能力，不为 Markdown / LaTeX 各做一套。
